# DeCodeMoMo

DeCodeMoMo 是一个密码解密实验项目。项目根据用户提供的提示、个人线索和实验反馈，设计候选密码生成算法，并把生成结果写入 TXT 文件，用于后续的离线验证实验。

这里的“解密”不是直接从密码中反推出明文，而是研究：当只掌握有限线索时，哪些密码构造规则最值得优先尝试。项目不会连接账户、钥匙串、备忘录或其他在线验证服务，也不会自动提交密码尝试。

## 实验分期

### 第一期：固定提示词排列组合

第一期的基本假设是：密码由若干提示词直接拼接而成。算法只对提示词做排列组合，再增加固定分隔符和大小写变体。

这种方法实现简单，但候选空间过于狭窄。它不能覆盖独立的自然数字、日期结构、数字片段、键盘输入变化或提示词之外的个人习惯。

第一期实验已经验证：生成并测试的候选均不是正确密码。因此，第一期的问题不是“候选数量还不够”，而是“密码构造规则的假设不成立”。

### 第二期：基于规则族的候选生成

第二期不再把提示词排列当作唯一模型，而是将线索拆成原子，并通过多个规则族生成候选：

- 文本变体：大小写、反转、截取、简单字符替换；
- 数字变体：完整数字、前缀、后缀、连续片段、倒序、去前导零；
- 日期和年份：不同年月日顺序、两位/四位年份和前后缀组合；
- 混合线索：保留原样、去分隔符、拆分后按原顺序重组；
- 拼音短句：只生成无空格拼音，并且优先级低于用户个人提示；
- 自然数字：递增、递减、重复数字和重复块，但权重最低；
- 长度阶段：先生成 `1..15` 位，再生成 `16..20` 位；
- 失败排除：读取第一期 TXT，已经验证失败的候选不再重复输出。

第二期默认输出 50000 条候选，写入新的 `toy_candidates_v2.txt`，不覆盖第一期基线。

### 第三期：只保留有明确含义的构造

第三期根据新的作者提示进一步收紧候选空间：密码不会使用无意义的数字或字符组合，也不会把已经给出的关键字翻转。

第三期因此取消以下规则：

- 通用纯数字、重复数字和递增递减序列；
- 文本、数字、混合线索及拼接结果的反转；
- 任意数字切片、简单字符替换和无来源分隔符；
- 提示词的任意排列组合。

保留的候选必须能够追溯到明确来源，包括提示原文、大小写变化、去除原有分隔符、长度不少于两位的原始数字片段、可识别的年份或有效日期，以及无空格拼音短句。跨提示组合只允许按照输入顺序连接相邻提示，不改变顺序，也不插入新字符。

第三期仍然先输出 `1..15` 位，再输出 `16..20` 位。个人提示及其变体优先于有序组合，有序组合优先于公开励志短句拼音。

作为失败基线，第三期分别读取 `toy_candidates_v1.txt` 和 `toy_candidates_v2.txt` 的前 10101 条；出现在任一前缀中的候选都不会写入 `toy_candidates_v3.txt`。

### 第四期：重复语义片段和跨位置组合

第三期实验失败后发现，限制“只能连接相邻提示”会遗漏距离较远但有明确含义的关键字组合。第四期将不同提示中重复出现的最长片段识别为语义原子，并允许任意两个语义原子按两种顺序直接连接。

第四期仍不翻转关键字内部字符、不添加新分隔符，也不恢复通用自然数字。排除采用完整字符串匹配：某个单独原子已经失败，不会连带排除包含该原子的新组合。

第四期排除 v1、v2 各自前 10101 条以及完整的 v3 结果，输出写入 `toy_candidates_v4.txt`。新增中文线索只以拼音保存在本地提示文件中，不进入仓库。

### 第五期：作者画像驱动的排序

前四期的失败说明“密码等于提示词排列组合”这个前提本身有问题，也说明在“只能验证终值”的环境里，值得优化的不是候选覆盖面，而是**正确候选的排名**。

第五期因此不再设计新的字符串规则，而是先建立作者画像，再按可信度排序：

- 画像按人生线索分类（姓名、曾用密码、网名笔名、生日、星座、数字、联系方式等），分类和单条线索都可以设置权重；
- 候选只由完整线索拼接而成，不反转、不拆分已给出的密码、不插入分隔符，大小写只允许原样、词首大写、整体大写；
- 排序分数取“最弱组成线索的权重”，再按拼接的线索数量递减，并对超过 15 位的候选统一重罚，使 15 位以内的候选优先；
- 励志短句等低可信度来源被标记为尾部分类，既不参与组合，也永远排在提示词之后；
- 继续排除 v1、v2 各自前 10101 条以及完整的 v3、v4 结果。

第五期输出写入 `toy_candidates_v5.txt`。真实画像保存在本地 `author_profile.local.json`，仓库中只有脱敏模板 `author_profile.example.json`。

### 第六期：从作者旧密码反推书写习惯

第五期失败说明“整块拼接”这条路已经穷尽（v5 已覆盖所有 1～2 个线索直接相连的组合）。第六期不再增加线索，而是补齐**变换**：

- 符号分隔（旧密码 `wyy25805.0` 里出现过 `.`，所以高可信线索之间生成 `.` 与 `_` 形式）；
- 片段自我重复（旧密码 `168168` 的形态）；
- 版本号递增（旧密码尾部形如 `.0`，因此生成 `.1`～`.9` 和主号 ±1）；
- 新增可直接解释来源的原子：网名首字母缩写、出生年份、星座英文、网名出处《将进酒》的名句拼音片段。

评分与变换参数（长度阈值、超长惩罚、组合惩罚、分隔符集合与门槛、重复惩罚、版本号范围）全部移到画像的 `combination_rules` 里，之后每轮实验只改数据。第六期输出写入 `toy_candidates_v6.txt`。

### 第七期：单位置的手抖打错

第六期失败后加入的新假设：密码可能没设错，而是作者设置时多打或少打了一个字符。第七期只生成三种可以从手抖直接解释的形态——连击多出一个相同字符、漏打一位、结尾多敲一个数字——并允许打错后的线索继续与高可信短线索拼接。

变异只作用于权重 ≥ 84 且长度 ≤ 12 的线索，权重比原线索低 12 分，因此原线索永远排在打错版之前。第七期输出写入 `toy_candidates_v7.txt`，并自动把完整的 v6 结果加入排除基线。

## 本地运行

把个人线索逐行放在 `personal_hints.local.txt` 中。这个文件已加入 `.gitignore`，不会上传到 GitHub。

```bash
python3 toy_candidate_lab.py \
  --hints-file personal_hints.local.txt \
  --exclude toy_candidates_v1.txt \
  --output toy_candidates_v2.txt \
  --limit 50000
```

输出 TXT 每行只有一个候选值，不包含中文、评分或规则说明。

第三期运行命令：

```bash
python3 toy_candidate_lab.py \
  --phase 3 \
  --hints-file personal_hints.local.txt \
  --limit 50000
```

未显式指定 `--exclude` 时，第三期会自动使用 v1 和 v2 文件；未指定 `--exclude-prefix` 时，每个文件默认只读取前 10101 条。输出默认写入 `toy_candidates_v3.txt`。

第四期运行命令：

```bash
python3 toy_candidate_lab.py \
  --phase 4 \
  --hints-file personal_hints.local.txt \
  --limit 50000
```

第四期默认使用 v1、v2 和 v3 作为排除文件；由于 v3 少于 10101 条，因此会被完整排除。输出默认写入 `toy_candidates_v4.txt`。

第五期运行命令：

```bash
python3 profile_candidates.py
```

默认读取 `author_profile.local.json`，自动使用 v1/v2 各自前 10101 条与完整 v3、v4 作为排除基线，输出写入 `toy_candidates_v5.txt`。需要覆盖排除范围时可以显式传入：

```bash
python3 profile_candidates.py \
  --exclude-head toy_candidates_v1.txt \
  --exclude-head toy_candidates_v2.txt \
  --exclude toy_candidates_v3.txt \
  --exclude toy_candidates_v4.txt \
  --exclude-head-lines 10101 \
  --limit 50000
```

每轮实验只需要更新本地画像（新增或修改权重），再重新执行一次生成命令。

第六期使用同一条命令，输出默认为 `toy_candidates_v6.txt`，并自动把完整的 v5 结果加入排除基线：

```bash
python3 profile_candidates.py
```

第七期同样使用这条命令，输出默认为 `toy_candidates_v7.txt`。


```bash
python3 -m unittest discover -s tests -v

```

## 实验边界

本项目只适合对自己拥有的文件或账户进行离线候选整理和算法实验。候选生成不是成功保证；如果密码是随机生成、没有可利用线索，或密码验证对象与当前假设不一致，应优先使用密码管理器、系统钥匙串、旧设备备份或官方恢复流程。
